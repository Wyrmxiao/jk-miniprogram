## 一、架构总览：前后端分离

```
┌─ 页面层 pages/ ─────────────────────────┐
│  只负责渲染与交互，不碰数据库             │
└──────────────┬──────────────────────────┘
               ↓
┌─ 服务层 services/index.js ──────────────┐
│  auth user learn contest announce social agent │
└──────────────┬──────────────────────────┘
               ↓
┌─ 通信层 utils/request.js ───────────────┐
│  唯一出口 request(domain, action, params)│
│  统一处理 loading / 错误 / 401 重登      │
└──────────────┬──────────────────────────┘
               ↓ wx.cloud.callFunction
┌─ 云函数层（7 个域）─────────────────────┐
│  index.js 统一入口 → router.js 路由分发  │
│  → handlers/*.js 业务 → middleware 鉴权  │
│  → services 领域服务 → 云数据库/存储     │
└─────────────────────────────────────────┘
```

**扩展一个新功能只需要三步**（不动框架、不改通信层）：

1. `cloudfunctions/<域>/handlers/*.js` 加一个 async 方法
2. `cloudfunctions/<域>/router.js` 注册一行 `action: handler`
3. `miniprogram/services/index.js` 对应域加一个方法

页面直接 `services.contest.list(params)` 即可。

## 二、云函数域划分

| 域 | 云函数 | 职责 |
|---|---|---|
| auth | auth | 登录、实名认证、教师审核 |
| user | user | 用户资料、列表、角色设置 |
| learn | learn | 学习路线、打卡、成长记录、成果、能力雷达 |
| contest | contest | 竞赛库、筛选、奖励测算、我的竞赛、竞赛指导 |
| announce | announce | **通知与赛事公告**（教师发布） |
| social | social | 交流动态、评论、点赞、举报 |
| agent | agent | **智能体 API 预留** |

## 三、智能体接入预留

`cloudfunctions/agent/` 已搭好骨架，当前未启用（调用返回 503 提示，不影响其他功能）。

接入时只需两步：

1. 在 `agent/services/llm.js` 的 `PROVIDERS` 配置 `baseUrl / apiKey / model`
   （建议用云函数环境变量 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`）
2. 实现 `callLLM(messages)`，调用模型接口返回 `{ content, usage }`

前端 `services.agent` 的四个场景方法**无需改动**：

- `chat` 通用问答助手
- `suggestRoadmap` 按方向与水平生成学习路线
- `contestAdvice` 按竞赛与方向给备赛建议
- `reviewLog` AI 先点评学习记录，老师再复核

会话记录自动落 `ai_conversations` 集合，便于复盘与审计。

## 五、竞赛数据（学校 83 号文）

依据《重庆移通学院学生学科竞赛管理办法（修订）》（移通〔2026〕83号）：

- **级别定义**（第五条）：A=中国高等教育学会榜单内项目；B=对应省市级/赛区选拔赛及重庆市教委公布项目；C=学校批准的其他省市及以上；D=校级
- **学科分类**（第四条）：理工类（硬件类）/ 理工类（其他类）/ 人文社科类
- **已结构化数据**：A 类 80 项 + 重庆 B 类 33 项 = **113 项**，含校内承办单位、学科分类、适配方向，其中 **13 项**标记为院内重点（计算机/大数据/信息安全学院承办）
- **奖励测算**：学生奖励（含团队系数）、指导教师奖励、指导费三张表已按文件第十三条实现，位于 `cloudfunctions/contest/services/reward.js`

## 六、教师能力（两位教师）

教师角色由管理员在 users 表设置，或调用 `user.setRole`。教师可：

1. 审核学生实名认证（通过/驳回）
2. **发布通知与赛事公告**（可关联竞赛、置顶、推送站内通知）
3. 查看所带学生的学习记录并批注
4. 维护竞赛库、发布竞赛指导文章

## 七、审核合规前置

| 事项 | 说明 |
|---|---|
| 个人主体类目 | 个人主体可选类目有限，学生交流（UGC）存在审核不确定性，提审前需核实最新类目要求 |
| 学号姓名采集 | 属个人信息，必须先配置《用户隐私保护指引》并弹窗授权 |
| UGC 内容安全 | 当前仅本地敏感词兜底，上线前必须接入云调用 `security.msgSecCheck` / `imgSecCheck` |
| 无支付功能 | 不涉及 iOS 虚拟商品支付限制 |

> 以上以微信官方最新审核规范为准。
