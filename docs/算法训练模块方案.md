# 算法训练模块 · 开发方案 v1.2.0

> 需求来源：学生在准备算法类竞赛（蓝桥杯 / ACM-ICPC / 天梯赛 / 百度之星等），
> 需要**知道该刷哪些题、按知识点和难度循序渐进**，并能记录训练量、让教师看到进展。
>
> 已确认的产品决策：
> 1. **核心形态：题库驱动的专题训练** —— 按知识点分模块、按难度分层，学生按路径刷题
> 2. 第二形态：刷题打卡 + 训练量统计（不做排行榜）
> 3. 记录粒度：中等 —— 题名 + 难度 + 知识点标签 + 是否通过（链接/备注可选）
> 4. 可见范围：学生自己 + 教师

---

## 零、题目从哪来（本版新增，最重要）

> 这是 v1.1.0 的空缺。只做「记录」，学生仍然要自己找题；
> 真正的问题是「今天该刷哪道题」。所以题库必须先落下来。

### 0.1 数据源实测结论（2026-10-29 验证）

| 数据源 | 接口 | 可抓 | 题量 | 难度 | 知识点标签 | 结论 |
|---|---|---|---|---|---|---|
| **Codeforces** | `codeforces.com/api/problemset.problems` | ✅ 200 / 2.2MB | **11481** | **rating 800–3500，每 100 分一档，97% 有值** | 38 个英文标签 | ✅ **主数据源** |
| **力扣（中文站）** | `leetcode.cn/graphql/` | ✅ 200（需 UA + Referer） | **4484** | EASY/MEDIUM/HARD | 标签带 `nameTranslated` **中文译名** | ✅ **中文补充源** |
| 洛谷 | `luogu.com.cn/problem/list` | ❌ 302 反爬（需 JS 挑战，带 cookie 也拦） | — | — | — | ❌ 放弃，仅支持手填题名 |
| 牛客 | `ac.nowcoder.com` | ⚠️ 200 但无结构化题库接口 | — | — | — | ⚠️ 本期不接 |

**关键优势**：Codeforces 的 `rating` 是**精确数值**，不是「简单/中等/困难」三档模糊分类。
这让「按难度分层」可以做到很细——每个知识点都能排出 800→2200 的阶梯。
其它平台做不到这一点。

### 0.2 精选题库规模（**已实跑生成，非估算**）

策略：每个 (知识点 × 难度档) 取通过人数最多的前 20 题（`solvedCount ≥ 100`，滤掉冷门题）。
双源并行：Codeforces 为主（精确难度分），力扣补中文题与 CF 无对应标签的知识点。

| 知识点 | 入门 | 基础 | 提高 | 进阶 | 挑战 |
|---|---|---|---|---|---|
| 模拟枚举 | 20 | 20 | 20 | 20 | 20 |
| 排序 | 20 | 20 | 20 | 20 | 20 |
| 二分 | 20 | 20 | 20 | 20 | 20 |
| **前缀和差分** | 20 | 20 | 20 | **0** | **0** |
| 双指针 | 20 | 20 | 20 | 20 | 20 |
| 贪心 | 20 | 20 | 20 | 20 | 20 |
| **递归分治** | 20 | 20 | 20 | 20 | 20 |
| 动态规划 | 20 | 20 | 20 | 20 | 20 |
| 图论 | 20 | 20 | 20 | 20 | 20 |
| 树 | 20 | 20 | 20 | 20 | 20 |
| 数据结构 | 20 | 20 | 20 | 20 | 20 |
| 字符串 | 20 | 20 | 20 | 20 | 20 |
| 搜索 | 20 | 20 | 20 | 20 | 20 |
| 数学 | 20 | 20 | 20 | 20 | 20 |

**实跑结果（2026-10-29，含中文翻译）**：**820 道去重题**，210 KB，
数据源 Codeforces 696 + 力扣 124，**中英文题名 100% 全覆盖**：

- 力扣 124 道：走官方 `translatedTitle`（如「区域和检索 - 数组不可变」）
- Codeforces 696 道：走 MyMemory 免费翻译接口（并发 3 + 本地缓存 `tools/.algo_title_cache.json`，
  已 gitignore），全部译出（如 Watermelon→清爽西瓜、Compatible Numbers→兼容号码）。
  部分专有名词为直译，**详情页同时展示中文译名与英文原名**，做题时以官方英文题面为准。

**两个真实发现（只有跑了才知道）**：

1. **`前缀和差分` 在 Codeforces 没有对应标签** —— CF 把这类题归到 `dp` 或 `implementation`，
   单靠 CF 这一档是 **0 题**。必须靠力扣的 `prefix-sum` 标签补，才凑出前 3 档。
2. **`递归分治` 低难度档 CF 近乎无题** —— 入门档 0 题、基础档仅 2 题。
   CF 低分题很少考分治。靠力扣 `divide-and-conquer` / `recursion` 补齐后才有 20 题。

> 单跑 CF 得 696 题但「前缀和」全空；双源合并得 820 题且 12/14 知识点满格。
> 剩下 2 个空格（前缀和的进阶/挑战）**如实留空**，页面显示「本档题目较少」，
> 不硬凑不适龄的题——凑出来的题会浪费学生时间。

### 0.3 题目存哪：构建时生成静态 JSON，不进数据库

```
cloudfunctions/learn/data/algo_problems.json     ← 构建产物（已生成，820 题 / 200KB）
tools/build_algo_problems.js                     ← 生成脚本
```

理由（重要）：

- **不进数据库**：820 道题若存数据库，每次筛选要查表 + 分页，还得处理索引与同步；
  而题库是**只读的、变更极慢的**，本质是一份静态字典。
- **随云函数部署**：云函数内 `require('./data/algo_problems.json')` 直接读，零网络、零延迟。
- **体积可控**：200KB。云函数包上限 20MB，无压力；且**不占小程序主包**。
- **可重现**：脚本记录筛选规则，任何人重跑都得到同样题库；换数据源只需改脚本。
- **刷新方式**：手动执行 `node tools/build_algo_problems.js --with-lc`，
  重新部署 learn 云函数即可。不需要定时任务——题库变动以年为单位。

文件结构（每道题精简到只留必要字段）：

```json
{
  "id": "cf:1:A",
  "title": "Theatre Square",
  "titleCn": "",
  "source": "codeforces",
  "pid": "1A",
  "url": "https://codeforces.com/problemset/problem/1/A",
  "rating": 1000,
  "band": "entry",
  "tags": ["math"],
  "solved": 240000
}
```

力扣题额外带 `pidDisplay`（题号，如 `"724"`）与 `titleCn`（中文名）。

### 0.4 难度档位（5 档，固定）

| band | 文案 | CF rating | 对应水平 |
|---|---|---|---|
| `entry` | 入门 | 800–1000 | 会语法就能做，建立信心 |
| `basic` | 基础 | 1100–1300 | 掌握基本套路 |
| `improve` | 提高 | 1400–1600 | 省赛 / 蓝桥杯省一水平 |
| `advanced` | 进阶 | 1700–1900 | 省赛获奖、区域赛打铁区 |
| `challenge` | 挑战 | 2000–2200 | 区域赛夺牌 |

> **不做「自动推荐难度」**——依据学生通过率自动推题会增加复杂度且效果存疑。
> 改为学生自选当前档位（首次进入默认 `entry`），可在设置里改。

## 一、为什么不做成「学习记录」的复用

现有的 `learning_logs`（学习记录）是**长文本复盘**：标题 + 正文 + 图片，一条记录代表一次学习心得。
算法刷题的特征完全不同：

| 维度 | 学习记录 | 算法刷题 |
|---|---|---|
| 频率 | 每周 1~3 条 | 每天 1~20 条 |
| 内容长度 | 几百字 + 配图 | 一行元数据 |
| 核心价值 | 复盘反思 | 量的积累与分布 |
| 统计需求 | 无 | 连续天数、知识点分布、目标进度 |

拿长文本表结构装高频短记录，会导致：录入太重学生不用、统计做不出来、列表一屏只能看两条。
所以**新建独立集合与独立页面**，但完全复用现有的鉴权上下文、教师评语机制与设计系统。

## 二、数据模型

### 2.1 集合 `algo_records`（打卡明细，一人一天多条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 主键 |
| `openid` | string | 归属学生 |
| `date` | string | 打卡日期 `YYYY-MM-DD`，用于聚合与去重 |
| `title` | string | 题名（必填，≤60 字） |
| `platform` | string | 平台：`luogu` / `codeforces` / `leetcode` / `nowcoder` / `atcoder` / `other` |
| `difficulty` | string | `easy` / `medium` / `hard` |
| `tags` | string[] | 知识点标签，见下方固定表 |
| `passed` | boolean | 是否 AC（未通过也计入训练量，但单独统计） |
| `url` | string | 题目链接，可选 |
| `note` | string | 思路备注，可选，≤200 字 |
| `source` | string | `self`（自主刷题）/ `task`（教师题单） |
| `taskId` | string | 关联学习任务，可选 |
| `authorName` | string | 冗余姓名，便于教师端列表直接渲染 |
| `teacherComment` | string | 教师评语（对齐 `learning_logs` 既有字段名） |
| `commentBy` | string | 评语人姓名 |
| `createdAt` / `updatedAt` | Date | 服务器时间 |

> **写入口径**：`date` 取用户本地日期（前端传），服务端校验不得晚于今天、不得早于 30 天前，
> 防止补打卡刷出虚假连续天数。

### 2.2 集合 `algo_stats`（聚合统计，每人一行）

写入 `algo_records` 时同步更新，避免统计页做全表扫描。

| 字段 | 说明 |
|---|---|
| `openid` | 唯一键 |
| `totalCount` / `passedCount` | 累计提交数 / 累计通过数（终身） |
| `byDifficulty` | `{ easy: n, medium: n, hard: n }` |
| `byTag` | `{ dp: n, graph: n, ... }` |
| `byDate` | `{ '2026-10-25': 7, ... }`，**只保留最近 120 天**，写入时裁剪 |
| `streak` / `maxStreak` | 当前连续天数 / 历史最长 |
| `lastDate` | 最后一次打卡日期，用于判断连续是否中断 |
| `goal` | 备赛目标：`{ contestId, contestName, targetCount, deadline }`，可为空 |
| `updatedAt` | 服务器时间 |

**连续天数算法**（写入时增量计算，不依赖查询）：

```
今天 = YYYY-MM-DD
若 lastDate == 今天        → 同一天多次打卡，streak 不变
若 lastDate == 昨天        → streak += 1
否则                       → streak = 1
maxStreak = max(maxStreak, streak)
```

### 2.3 知识点标签（固定 14 项，写死在 constants，前后端共用）

| key | 文案 | key | 文案 |
|---|---|---|---|
| `simulation` | 模拟枚举 | `dp` | 动态规划 |
| `sort` | 排序 | `graph` | 图论 |
| `binary` | 二分 | `tree` | 树与二叉树 |
| `prefix` | 前缀和差分 | `ds` | 数据结构 |
| `twopointer` | 双指针 | `string` | 字符串 |
| `greedy` | 贪心 | `math` | 数学 |
| `recursion` | 递归分治 | `search` | 搜索（BFS/DFS） |

固定枚举而非自由输入，理由：自由标签会让统计图变成一团噪声，且无法做「薄弱项」判断。

## 三、接口设计（并入 learn 域，不新建云函数）

遵循项目约定：**handlers 加方法 → router 注册 → services 加方法**。新增 11 个接口。

### 3.1 题库驱动（新增 4 个）

| action | 权限 | 入参 | 出参 |
|---|---|---|---|
| `algoProblemModules` | 登录 | — | 13 个知识点的题量矩阵（各档位题数），供模块选择页直接用 |
| `algoProblemList` | 登录 | `tag, band, page, size, onlyTodo?` | 该模块该档位的题目列表，带 `done` 标志（我已通过/未做） |
| `algoProblemDetail` | 登录 | `id` | 单题详情 + 我的完成状态 + 同知识点相邻题 |
| `algoMarkProblem` | 登录 | `id, passed` | 标记该题完成/撤销，**自动生成一条打卡记录** |

> **核心设计**：`algoMarkProblem` 把「做题」和「记录」合并成一个动作。
> 学生不用先做题、再去另一处填表单——点了「通过」就自动落一条 `algo_records`，
> 统计同步更新。这才是刷题场景该有的交互。

### 3.2 记录与统计（沿用 v1.1.0，7 个）

| action | 权限 | 入参 | 出参 |
|---|---|---|---|
| `algoCheckIn` | 登录（本人） | `date, title, platform, difficulty, tags[], passed, url, note` | `{ id, stats }`，用于手动补记（洛谷/牛客等外站题） |
| `algoRecords` | 登录 | `page, size, openid?, tag?, difficulty?, passed?, from?, to?` | `{ total, list, page, size }` |
| `algoRecordDetail` | 登录 | `id` | 记录全文 + 权限校验 |
| `algoRemove` | 本人或管理员 | `id` | `{ id }`，同步回滚统计 |
| `algoComment` | 教师/管理员 | `id, comment` | `{ id, teacherComment }` |
| `algoStats` | 登录 | `openid?`（教师可查他人） | 统计全量 + 最近 84 天日题量（热力图） |
| `algoSetGoal` | 本人 | `contestId, targetCount, deadline` | `{ goal }` |
| `algoTeacherOverview` | 教师/管理员 | `page, size` | 按学生汇总：题数 / 通过率 / 连续天数 / 最近打卡 |

**关键实现要点**

- `algoRecords` 的可见性完全在服务端判定：
  `ctx.isTeacher ? (openid || 全部) : ctx.openid`，前端传什么都越不过去。
- `algoRemove` 必须**反向扣减** `algo_stats`（`byTag` 减到 0 时删 key；`byDate` 减到 0 时删日期，
  并重算 `streak`——按 `byDate` 从今天往前数连续天数，这是唯一可靠的兜底方式）。
- `algoTeacherOverview` 用 `algo_stats` 一次查回，再用 `users` 补姓名，避免 N+1。
- 全部接口写操作前调 `ensure('algo_records')` / `ensure('algo_stats')`，沿用集合自愈机制。
- **题目完成状态不单独建集合**：直接用 `algo_records.problemId` 反查。
  记录本身就是「我做过这道题」的凭证，天然避免两套数据不一致。
  列表查询时把该生 `problemId` 集合一次取回做内存标记（706 题规模，可接受）。

**`[通过]` 按钮直接调 `algoMarkProblem`**，成功后：
- 该行变成 ✓
- 顶部进度 +1
- 全站统计同步更新

**`pages/algo/problem` 交互**

题目名 / 难度分 / 标签 / **复制题目链接**（沿用赛事详情页的合规做法：
个人主体无业务域名，不能 web-view，只能复制 + 引导浏览器打开）/ 我的历史记录 / 备注输入 /
「同知识点下一题」快捷跳转。

- 打卡走底部弹层（`.mask` + `.sheet`，`catchtap="noop"`），不跳页——刷题场景要在列表里连续录入。
- 弹层内知识点用 `.opt` 多选 chips（复用现有 `monthSel/tagSel` 那套查表对象模式，**禁止在 WXML 调方法**）。
- 难度三档用 `.seg` 分段控件。
- 日期默认今天，可回改近 30 天（配 `wx.date-picker` 等价的自定义选择，避免引入新组件）。
- 打卡成功后**本地插入列表顶部 + 更新统计卡**，不做整页刷新。
- 未认证用户进入时，显示「去认证」引导（与 learn 页一致），打卡按钮置灰。

### 4.3 记录详情 `pages/algo/detail`

时间 / 难度 / 标签 / 平台 / 链接（复制而非 web-view，沿用赛事详情页的合规做法）/
备注 / 教师评语。教师在此页评语。

### 4.4 入口

学习页 `pages/learn/learn` 的 hero 下方新增一个 `.group` 入口 cell：

```
📐 算法训练        连续 12 天 · 今日已完成  ›
```

显示今日状态（已打卡 / 未打卡），点击进入训练主页。**不动现有 seg 两 tab 结构**——
避免把「任务/记录」的语义撑散。

### 4.5 教师视角

训练主页对教师显示切换：「我的训练 / 学生训练」。
学生训练视图 = `algoTeacherOverview` 列表（姓名 + 题数 + 通过率 + 连续 + 最近打卡），
点进去看该生全部记录，可评语。

### 4.6 用户操作逻辑（全流程）

**学生 · 第一次进入**

```
学习 tab → 「📐 算法训练」入口卡（显示「开始你的第一次刷题」）
  → 训练主页：空状态引导页（三选一）
      ① [从题库开始] → 选知识点模块 → 选难度档 → 题单 → 做题
      ② [记录外站题] → 打卡弹层（洛谷/牛客等手动补记）
      ③ [设置备赛目标] → 选目标赛事 + 目标题数 + 截止日期
```

**学生 · 日常刷题（最高频路径，3 步以内）**

```
训练主页 → [去刷题]（或「今日推荐：接着上次」卡片直达上次的模块档位）
  → 模块页：点「动态规划」（进度 3/20）
  → 题单页：做题 → 回来点该题 [通过]
      → 行变 ✓、进度 +1、toast「已记录，今日 +1 题」
      → 底部出现「下一题 →」直达按钮，继续刷
```

关键设计：**标记通过的地点就在题单页**，不跳详情页。详情页只在
「复制链接去官方做题 / 写备注复盘 / 看教师评语」时才进。

**学生 · 查看进展**

- 训练主页常驻：统计三卡（累计/通过率/连续天数）+ 12 周热力图 + 知识点分布条
- 热力图/进度条每次标记后即时更新，无需刷新

**学生 · 手动补记外站题（洛谷/牛客等）**

```
训练主页 → [+ 补记] → 弹层：题名（必填）/ 链接 / 难度 / 知识点标签 / 是否通过
  → 提交 → 与题库记录汇入同一统计
```

**教师**

```
学习 tab → 算法训练入口 → 主页顶部 seg 切「学生训练」
  → 全班总览列表（姓名 · 累计题数 · 通过率 · 连续 · 最近打卡）
  → 点某学生 → 该生打卡流水 → 单条记录 → [写评语]
```

**边界情形**

| 情形 | 行为 |
|---|---|
| 未认证进入 | 显示「去认证」引导，所有写入按钮置灰（与 learn 页一致） |
| 某知识点某档位题量少（如前缀和·进阶） | 显示「本档题目较少」+ 建议跳相邻档位 |
| 学生点击 [通过] 但实际没做 | 这是自律记录不做判题校验，页面文案注明「记录以自觉为准」 |
| 断网 / 云函数失败 | request 层统一 toast，标记不落库、UI 不假更新 |

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 外部 API 不可用 / 限流 | 题库是**构建时快照**，运行时零依赖；脚本失败沿用上次 JSON，不影响线上 |
| 数据源版权 / 合规 | 只存题名、难度、标签、官方链接，**不存题面**；学生点链接去官方站点做题，属导航性质 |
| 学生刷量（一天记 200 题） | 单日同题名去重提示；`date` 服务端限制 30 天内；统计只做展示，不做排名（无排名即无刷量动机） |
| `algo_stats` 与明细不一致 | 每次写操作在同一逻辑里更新；另留 `algoRecalc`（管理员）按明细全量重算兜底 |
| 热力图渲染卡顿 | 84 格一次性 `setData`，用预计算的 `level` 字段（0~4）而非在 WXML 里算 |
| 主包体积 | 5 个页面约 40KB，当前主包 126KB，远低于 2MB；题库 JSON 在云函数包内不占主包 |
| 云函数包体积 | 题库 200KB，云函数上限 20MB，无压力 |
| 树/递归分治低档题量稀少 | 该档位显示「题目较少，建议先打基础」，不硬凑不适龄的题 |
| 个人主体类目 | 本模块无 UGC 公开展示、无社交，不触碰类目红线 |

## 九、明确不做（本期范围外）

- 排行榜 / 班内排名（已否决，且有审核与刷量风险）
- **在线判题（OJ）对接**：不代学生提交代码、不校验真实通过状态。
  「通过」由学生自己点，是**自律记录**而非判题结果，页面上必须说清。
- 洛谷题库抓取（有 JS 反爬，无公开授权接口）——仅支持手动补记题名
- 自动推荐难度（依据通过率推算，复杂度高且效果存疑）
- 题面离线缓存（版权风险，且题面更新频繁）
- 能力雷达图（需要六维主观自评，数据可信度低）
