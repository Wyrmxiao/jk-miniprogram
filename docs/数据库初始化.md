# 数据库与系统初始化说明

> 云环境：`cloud1-d5gr2v7tz34fafa7c`
> 更新日期：2026-10-16

系统初始化已做成**幂等接口**，跑一次即可完成建集合、指定管理员、导入竞赛库，
不需要在控制台手工建表。

## 一、一键初始化（推荐）

### 方式 A：小程序自动完成（零操作）

`miniprogram/app.js` 在首次启动时会自动执行：

1. `auth.bootstrap` —— 建集合、写系统配置、把**第一位使用者**提升为管理员
2. `contest.importSeed` —— 导入 113 项赛事

结果会打印到控制台，并在界面提示「竞赛库已导入 N 项」。
本地缓存 `csic_db_inited` 存在时不再重复执行。

### 方式 B：命令行驱动（可在 IDE 未打开时执行）

```bash
# 1. 部署全部云函数
cli.bat cloud functions deploy --project <项目路径> --env cloud1-d5gr2v7tz34fafa7c \
  --names auth user learn contest announce social agent --remote-npm-install

# 2. 开启自动化端口
cli.bat auto --project <项目路径> --auto-port 9420

# 3. 执行初始化（需在项目 tools 目录安装 miniprogram-automator）
node tools/init_remote.js          # 幂等初始化
node tools/init_remote.js force    # 覆盖重导竞赛库
node tools/verify_remote.js        # 全接口自检
```

初始化返回示例：

```json
{ "code": 0, "data": { "initialized": true, "justInitialized": true,
  "competitions": 113, "role": "admin",
  "collections": { "created": [17 个集合], "failed": [], "total": 17 } } }
```

## 四、安全规则

统一原则：**写操作只走云函数**，安全规则作为兜底。

- 私有集合（users、auth_applications、my_contests、learning_logs 等）

```json
{ "read": "doc.openid == auth.openid", "write": "doc.openid == auth.openid" }
```

- 公共只读集合（competitions、roadmap_templates、announcements）

```json
{ "read": true, "write": "doc.publisherOpenid == auth.openid" }
```

> 前端不直接访问数据库，全部经 `utils/request` → 云函数 → 数据库，
> 云函数内做二次角色校验。

## 五、管理员与角色分配

1. **第一位使用者自动成为管理员**：模拟器环境的 openid 与真机不同，
   真机首次登录时是游客，需由首位管理员在小程序内分配角色。
2. **分配角色（唯一途径）**：管理员打开「我的 → 用户与权限」，
   可按角色筛选、按姓名/学号搜索全部用户，并把任一用户设为
   `student` / `teacher` / `admin`（接口 `user.setRole`）。
   设为教师或管理员时自动置为已认证；不支持输入激活码自助提权。
3. **安全约束**：管理员不能修改自己的角色，系统始终至少保留一位管理员。
   两位教师建议都设为 `teacher`。

## 七、排查技巧

云函数统一响应 `{ code, msg, data }`。排障时在 `params` 里带 `__debug: true`，
500 错误会返回真实异常信息，而不是「服务异常，请稍后重试」：

```json
{ "action": "importSeed", "params": { "__debug": true } }
```
