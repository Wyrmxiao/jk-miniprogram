# v3 视觉改版 · 三方向卡

> 范围：全站五个 tab（首页 / 学习 / 竞赛 / 项目 / 我的）＋ 题目详情、学习问答。
> 主题：iPhone 设计语言，但字体、动效、交互要更像 2026 年年轻人用的 App，而不是学校系统。
> 三版都遵守 iOS 语言（连续圆角、材质、弹簧曲线、单手可达），差异落在**信息怎么组织**上，不是换个配色。

---

## 六个候选 → 三张方向卡

每个方向的「最佳设计师」与「现实参照」两个候选，只留能拉开差异的那个做成完整版。

### 方向 A · Liquid Glass 悬浮层

| | 候选 A1（采纳） | 候选 A2（弃） |
|---|---|---|
| 逻辑来源 | 最佳设计师：Apple 人机界面团队做 iOS 26 Liquid Glass 的那一版 | 现实参照：Nothing OS 的点阵黑白 |
| 骨架 | 全屏内容 → 玻璃卡片层叠 → 悬浮胶囊 Dock 离开底边 | 网格点阵底 + 荧光红单色 |
| 为什么留 | 玻璃与光斑给了「新」的质感，悬浮 Dock 是这一代 iOS 的识别点，也正好解决小程序底部 tabBar 死板的通病 | 点阵+单色更像硬件品牌，和校园内容无关，且对比度做不满 |

**一句话**：内容浮在光上面。
**字体**：SF Pro Display，标题 -0.035em 紧排，34/19/14.5/11 四阶，字重 800/680/550。
**动效**：光斑 19–27s 缓慢漂移（互相错相）；卡片 `scale(.965)` 按压缩回，曲线 `.34s cubic-bezier(.22,1,.36,1)`；进度环 1.4s 描线。
**交互**：Dock 选中项上浮 1px + 放大 1.06 + 渐变底；卡片整块可点，不用小箭头。
**风险**：小程序不支持 `backdrop-filter`，落地时用「半透明底 + 预渲染模糊光斑图」代替，视觉损失约 15%。

### 方向 B · 圆体数据流

| | 候选 B1（采纳） | 候选 B2（弃） |
|---|---|---|
| 逻辑来源 | 最佳设计师：Apple Fitness / Journal 的设计团队 | 现实参照：Strava 深色训练面板 |
| 骨架 | 首页不谈功能入口，只谈「今天」——环 + 时间线，按时间组织 | 深色 + 全屏地图轨迹 |
| 为什么留 | 把「学习」变成可量化的日常，连续天数/本周通过率天然有正反馈 | 地图对校园学习内容毫无意义，属于套模板 |

**一句话**：你的今天，不是一个菜单。
**字体**：Rounded 系（SF Pro Rounded → 落地用系统圆体 + 字重 800），数字 -0.055em 紧排，`tabular-nums`。
**动效**：环 `stroke-dashoffset` 1.5s 描线；数字滚动；横滑卡片 snap；按压缩放用 `.3s cubic-bezier(.3,1.4,.5,1)`（带回弹）。
**交互**：时间线节点可点进题目；底部四项用「横条 + 标签」表达选中，选中条从 26px 弹到 34px。
**风险**：深色底 + 荧光绿在户外强光下不如浅色可读；需要提供浅色镜像。

### 方向 C · 编辑排版

| | 候选 C1（采纳） | 候选 C2（弃） |
|---|---|---|
| 逻辑来源 | 现实参照：App Store「Today」+ Apple Music 编辑推荐 | 最佳设计师：原研哉式极简（大留白 + 无彩色） |
| 骨架 | 头版大标题 → 一根 1px 线 → 线框列表；全场不用卡片 | 同样留白，但用衬线中文 + 无强调色 |
| 为什么留 | 字号跨度把层级讲清楚了，页面轻、加载快、和小程序的渲染约束天然合拍 | 无彩色在大屏好看，在 390px 宽的校园工具里会显得没重点 |

**一句话**：把校园做成一本杂志。
**字体**：标题 46px / 25px，正文 15.5px 行高 1.78，标签 11px；标题 -0.055em，正文 -0.008em。
**动效**：`stagger` 每条延迟 60ms 上浮 18px 进场；分隔线 `scaleX(0→1)` .7s 生长；荧光笔划线 0.7s 从左展开。
**交互**：整行可点；tab 用「文字 + 底部 2px 线」；进度用 2px 细条而不是圆环。
**风险**：无卡片意味着信息密度低，任务多（>8 条）时列表会拉得很长，需要折叠。

## 三版共用的底线

- 正文最小 15.5px（≈31rpx），标签最小 11px（≈22rpx），不为了「高级」牺牲可读性
- 正文对比度 ≥ 4.5:1：A 用 #0E0E12 / #FCFBF9，B 用 #F4F4F6 / #08080B，C 用 #101014 / #FCFBF9
- 不用 01/02/03 编号装饰、不在标题上方堆全大写小标签、不给按钮加无意义箭头 —— 三版都守住了
- 三版展示板构图各不相同：A 深空光斑 + 主屏放大错落，B 深黑阶梯斜降，C 纸白平铺 + 图注

## 附：方向 A 字体改版（已执行）

用户反馈「参考 A，字体改得更灵动圆润」，改动落在 `dir-a.html`，对照页见 `compare.html`。

### 改了什么

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 中文字形 | 苹方 / 系统黑体 | 圆体（笔末圆角、转角带弧） | 黑体端点平切，是"系统感"的主要来源 |
| 数字 / 拉丁 | 系统默认数字 | Nunito 400–900 | 圆润几何，820 / 70% / 天数这些数字变成整块圆润形，是"灵动"最省力的落点 |
| 标题字重 | 800 | 400（圆体天然字重） | 圆体只有一个字重，硬压 800 会糊 |
| 大字标题 | 34px / −0.035em | 40px / +0.01em / 行高 1.22 | 圆体字面比黑体小约 8%，字号要补；字距必须放正，紧排会把圆体的弧挤掉 |
| 全站字距 | −0.035 ~ −0.012em | +0.008em | 负字距 = 锐利；圆润需要字与字之间有空气 |
| 强调 | 加粗 | 加粗 + 主色蓝 | 圆体合成粗体力度弱，"偶数"这类强调单靠粗体不够 |

### 一条纪律

**圆体只做"脸"，不做"身体"。** 大字标题、数字、按钮、标签用圆体；长正文虽然也跟了圆体，但行高保持 1.78，靠行距换可读性。如果后续发现长正文吃力，回退到「标题圆体 + 正文系统黑体」的分层即可，令牌不用改。

### 落地约束（重要）

1. **幼圆（YouYuan）不能进小程序**。它是 Windows 自带、中易字库版权，不可嵌入分发；且 iOS / Android 根本没有这个字体。原型用它只是为了让"圆润"这个目标长得出来。
2. **落地请换开源可商用圆体**，首选 **Resource Han Rounded CN**（思源柔黑的圆角版，SIL OFL，7 个字重 —— 顺带解决"只有一个字重"的层级问题）；备选 jf open 粉圆（繁体为主，简中缺字）。
3. **必须子集化**。全量简中圆体 6–8MB，微信主包只有 2MB。只保留 UI 实际用到的字（约 2500–3500 个），woff2 可压到 300–500KB，放分包或 CDN。
4. **加载方式**：`wx.loadFontFace({ family, source: 'url("https://…woff2")', global: true })`，字体文件走 HTTPS，域名在小程序后台配置。加载失败必须回落系统字体，不能白屏。
5. 若不愿承担字体体积，退一步的方案是：**中文保持系统黑体，只把数字与拉丁换成 Nunito 子集**（约 30KB）。圆润感会损失大半，但零风险、零版权问题。
